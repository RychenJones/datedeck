# DateDeck style guide · DD-07

DateDeck uses a dark charcoal canvas, rounded panels, coral accents, and friendly rounded type. The supplied Deck and All ideas references define the layout. `frontend/src/styles/index.css` is the shared source of design tokens; `Home.jsx` owns the React header and layout. Both `index.html` and `datedeck.html` mount the same React app.

| Token family                                           | Use                                                                 |
| ------------------------------------------------------ | ------------------------------------------------------------------- |
| `--page`, `--panel`, `--field`                         | Canvas, cards, and input backgrounds                                |
| `--ink`, `--muted`, `--line`                           | Primary text, secondary text, and borders                           |
| `--accent`, `--on-accent`                              | Coral highlights and their foreground                               |
| `--action`, `--on-action`, `--action-hover`            | Light action buttons and selected navigation                        |
| `--cozy` through `--night-out`, `--on-mood`            | Category pills and their foreground                                 |
| `--font-body`, `--text-*`, `--weight-*`, `--leading-*` | Fredoka with local fallbacks, type scale, weights, and line heights |
| `--space-1` through `--space-12`                       | Spacing scale from 4px to 64px                                      |
| `--radius-*`                                           | Small controls, panels, cards, deck corners, and pills              |
| `--control-*`, `--icon-*`                              | Consistent control and icon sizes                                   |
| `--art-*`, `--shadow-*`, `--focus`                     | Illustration palette, elevation, and keyboard focus                 |

**Visual direction.** Treat the two screenshots as views of the same app: a charcoal canvas, slightly lighter rounded surfaces, off-white text, muted secondary text, coral highlights, and pastel illustrations. Keep the interface friendly and spacious. Use the same palette, type family, corner shapes, and control styles in Deck, All ideas, Liked, and the saved list. The screenshots establish the visual hierarchy, not fixed page heights or hard-coded example counts.

**Typography and spacing.** Use `--font-body` throughout. Use `--weight-heavy` for the wordmark, `--weight-bold` for headings and important actions, and `--weight-medium` or `--weight-regular` for supporting text. Card titles use `--text-xl`; the featured Deck title uses `--text-deck`; section headings use `--text-heading`. Place names and metadata use `--text-md` with `--muted`. Use `--leading-heading` for headings and `--leading-body` for descriptions. Let long titles wrap. Choose gaps and padding from `--space-*`; leave more space between sections than between related labels and controls.

**Surfaces, corners, and imagery.** Use `--page` for the canvas, `--panel` for filters/cards/saved items, and `--field` for inputs and inset detail tiles. Use `--radius-card` for cards and the filter panel, `--radius-deck` for the featured card, `--radius-lg` for compact saved items and detail tiles, and `--radius-pill` for chips and primary buttons. Keep cards borderless with only the subtle `--shadow-card`; reserve `--line` for places that need separation. Photos and illustrations must fill their image areas, clip to the card's top corners, and preserve their proportions. Use `--art-*` for flat placeholder artwork: peach food scenes, pale blue outdoor scenes, pink cozy scenes, and purple night scenes. Decorative artwork must not compete with the title or replace actual date details.

**Layout.** On wide desktop screens, use three aligned columns below the header: filters on the left, the main view in the wider center, and Saved for later on the right. The side columns have similar widths; the center is approximately twice as wide. Keep column gaps generous and align the top of the filter panel with the main content's toolbar/count area. The saved heading begins near the top of the cards, below the toolbar. Center the Deck stack within the middle column; use a two-column card grid for All ideas.

Base styles target phones, including 320px and 375px. Below 640px, use a single-column card grid and stack the main layout sections. From 640px, the grid can use two columns when card content and controls fit. At 800px, filters sit beside the content and the saved list follows below; navigation keeps its own header row. At 1280px, the header fits on one row and filters, results, and saved ideas form three columns. The 1700px breakpoint scales the reference layout for large screens. Use `minmax(0, 1fr)` and `min-width: 0` so content can shrink without sideways scrolling. Let the page scroll vertically instead of clipping cards to the screenshot height.

**Header style (template references).** Keep the header on the page background (`--page`), without an enclosing card, divider, or shadow. On desktop, align the brand, navigation, and actions vertically: brand on the left, grouped view buttons beside it, and theme/Add idea actions at the far right. Leave a generous gap below the header using `--space-8` on phones and `--space-9` from 800px.

- **Brand:** lowercase `datedeck`, using `--font-body`, `--weight-heavy`, `--tracking-tight`, and `--ink`. Place a solid white heart (`--on-accent`) inside a coral (`--accent`) rounded square with `--radius-md` and a slight counterclockwise tilt. Use `--icon-large` for the heart. Scale the wordmark from `--text-xl` to `--text-heading` at 480px and `--text-brand` at 800px.
- **Navigation:** one dark `--panel` capsule with `--radius-pill` and `--space-1` inset padding. Keep Deck, All ideas, and Liked in that order; the added Liked tab uses the same styling as the two template tabs. Each button pairs an outline icon with a rounded, bold label. Inactive buttons use `--muted` on a transparent background; the selected button uses `--action` with `--on-action` text and icon. Keep the selected button fully rounded rather than using an underline or rectangular highlight.
- **Actions:** show the outlined sun icon in a circular `--panel` button, followed by a light `--action` pill containing a plus icon and `Add idea` in `--on-action`. Use `--weight-bold` for the label, `--text-sm` on phones, and `--text-lg` from 800px. Center the icons and labels vertically. Use `--action-hover` for the Add idea hover state and `--field` for the theme hover state.
- **Sizing and spacing:** use `--control-small` for the 44px minimum targets. From 800px, use `--control-large` for the brand mark, theme circle, and minimum tab height; the Add idea pill is `calc(var(--control-large) + var(--space-2))` tall. From 1700px, the brand mark and theme circle are `calc(var(--control-large) + var(--space-1))` square. Use existing `--space-*` tokens for icon gaps, pill padding, and separation between header groups.
- **Responsive layout:** below 1280px, keep navigation on its own full-width row with equal-width buttons. Below 480px, place each tab icon above its single-line label so all three tabs fit at 320px and 375px without horizontal scrolling. From 480px, place icons beside labels. At 1280px and above, use a single header row with navigation sized to its contents. Preserve readable labels, visible `--focus` rings, and the same shapes and selected-state contrast in the light theme.

**Filter panel.** Use one rounded `--panel` container with generous padding and the heading `Find your mood`. Order the controls as shown: search, mood/category chips, party size, budget and time, indoor/outdoor choice, then time-of-day and display options. The search field is a wide `--field` pill with an outline search icon and muted placeholder. Category chips use their existing category color tokens with `--on-mood` text and a nearby count. Segment groups use a `--field` capsule with the selected option on a darker `--panel` inset. Dropdowns use rounded `--field` surfaces and muted chevrons; align paired fields in two equal columns. The secondary Add your own idea action is a transparent rounded button with a dashed outline and plus icon.

**All ideas cards.** Use a two-column desktop grid with consistent horizontal and vertical gaps. Each card has a shallow illustration/photo area above a `--panel` body; use the reference's roughly 600:260 image ratio. Inside the body, order the content as category pill, prominent title, muted place, then duration/price/party-size metadata when available. Use comfortable side padding and keep content left-aligned. Put outline actions in a separate bottom row, with liking/completion on the left and editing/removal on the right when those actions are available. Keep action placement consistent and avoid crowding long metadata. A liked heart should have a visibly filled selected state; unavailable actions must not appear active.

**Deck card.** Show one larger card with two subtly rotated, colored cards behind it. Keep the front card upright, centered, and bounded by `--deck-width`. Its illustration/photo occupies a taller area than a grid card (roughly 600:356). Use a category pill, a large wrapping title, muted location with a pin icon, readable description, and rounded inset tiles for duration, price, and party size when supplied by the data. Keep the edit action in a light circular button at the image's top-right only when editing is available. Below the card, center the circular controls: smaller subdued Undo, larger Hide, dominant coral heart, and smaller purple Shuffle. Use `--control-*`, `--accent`, `--on-accent`, and `--shuffle`; keep these controls within reach on phones and show a clear count above the stack.

**Saved for later.** Use a section heading with a small coral circular count badge. Each compact saved item uses a rounded `--panel` surface, square rounded thumbnail, title and muted metadata, and a trailing outline remove icon. Keep rows vertically centered with consistent gaps. Titles may truncate to one line in this compact list only if their full text remains accessible; metadata can wrap. The Pick one from saved action uses a full-width light pill with a dice icon and dark bold label when that feature is available.

**Liked view.** Reuse the All ideas card style and grid for liked activities; do not introduce another palette or card system. Keep the third header tab visually consistent with Deck and All ideas. Show the actual liked count, selected hearts, and the same spacing as the other views. For an empty list, use a rounded `--panel` message with a clear heading, muted explanation, and a light pill action back to All ideas.

**States and accessibility.** Use real buttons and associated labels. Every icon-only action needs an accessible name; decorative SVGs are hidden from assistive technology. Retain visible `--focus` rings, at least 44px action targets, and readable contrast in both themes. Use `--action-hover` or existing surface tokens for hover feedback, and make selection visible through shape/fill as well as color. Honor reduced-motion preferences. Loading, error, empty, and disabled states must use the same type and surface system and explain their meaning. Keep descriptions readable rather than clipping text to imitate a cropped screenshot. Never invent date metadata or display placeholder counts as real data.

**Light theme.** Preserve the layout, radii, illustrations, and visual hierarchy. Swap canvas/surface/text colors through the existing theme token overrides, keeping strong foreground/background contrast. Do not hard-code a separate component palette or style values inline in JSX.

**Visual review.** Compare Deck and All ideas with the supplied screenshots, then confirm that Liked uses the same design language. Inspect the header, filter panel, card shapes, image cropping, title/metadata hierarchy, action alignment, and saved list at the reference desktop sizes and at 320px, 375px, 800px, and 1280px. Check both themes, keyboard focus, long titles, wrapped metadata, and empty/error states. Use the project's lint, test, and build checks as applicable; passing code checks alone does not establish visual fidelity.
